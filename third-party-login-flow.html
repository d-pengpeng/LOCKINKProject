🔐 App 第三方登录通用流程图

适用于：微信 / QQ / Apple Sign in / Google / Facebook / Twitter 等 OAuth2 / OpenID Connect 渠道

flowchart TD
    A([用户打开 App 登录页]) --> B{选择登录方式}
    B -->|手机号+验证码| PHONE[[手机号登录
不在本流程范围]]
    B -->|第三方账号| C[点击第三方登录按钮

    C --> D{是否安装第三方 App?}
    D -->|已安装| E[调起第三方 SDK
OpenURL / Universal Link]
    D -->|未安装| F[跳转第三方 Web 授权页
H5 Safari / SFSafariViewController]

    E --> G{第三方授权}
    F --> G
    G -->|用户取消| X([登录失败 / 返回])
    G -->|用户同意授权| H[第三方返回 auth code / identityToken]

    H --> I[App 将 auth code 发给后端]
    I --> J((后端))
    J --> K[后端用 code 向第三方
换 access_token + userinfo]
    K --> L{请求第三方 API}
    L --> M[拿到第三方 openid / unionid / email / 头像]

    M --> N{本地用户表是否
存在该 third-party id?}
    N -->|✅ 已绑定| O[查到已有用户记录]
    N -->|❌ 未绑定| P{是否首次使用?}
    P -->|🆕 新用户| Q[自动创建账号
绑定 third-party id]
    P -->|🔁 老用户换了设备| R[进入绑定流程
要求输入手机号/验证码]

    O --> S[后端生成 JWT / Session]
    Q --> S
    R --> S

    S --> T[返回 JWT + 用户信息
给 App]
    T --> U[App 存储登录态
UserDefaults / Keychain]
    U --> V([进入首页 / 登录成功])

核心思路：App → 第三方 → App → 自己后端 → 第三方(取 userinfo) → 自己后端(查/建用户) → 发 JWT
App 端职责：调起 SDK、处理回调、暂存 code、把 code 发给后端、保存登录态
后端职责：code 换 token、拉 userinfo、用户表匹配/创建、发 JWT、管理过期与刷新
安全要点：App 永远不要直接把第三方 access_token 存到本地信任它；必须经过自己后端二次换取和校验。Apple / Google 的 identityToken 是 JWT，后端要验签名和 exp。
新用户策略：可以直接一键创建（减少摩擦），也可以要求绑定手机号（合规要求）。取决于产品和监管需求。
